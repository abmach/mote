Patterns and recipes

These recipes cross several sections of mote. Each one names the page-owned CSS explicitly so the library boundary stays clear.

Patterns

Compositions that span multiple topics — each piece is documented in the topic pages; these show how they fit together. Copy, paste, adjust.

Error page

A full-height centered page with a themed giant code, search, and quiet CTAs — body class="mote-error" tints everything except the actions (theming, display text, buttons):

<body class="mote-error">
  <header>Site header</header>
  <main class="mote-container mote-hero">
    <p class="mote-display">404</p>
    <p>This page drifted away.</p>
    <form class="mote-row" role="search" style="justify-content:center">
      <label class="mote-sr-only" for="q">Search</label>
      <input id="q" type="search" placeholder="Search…">
      <button type="submit">Go</button>
    </form>
    <p>
      <a class="mote-btn" href="/">Back home</a>
      <a class="mote-ghost" href="/docs">Read the docs</a>
    </p>
  </main>
</body>

Article page

A narrow reading-measure article with breadcrumb, byline, tags, and an author box — --mote-container-max narrows the column (Simple page, badges as links, media objects):

For a companion TOC and numbered references, continue with Long-form reading with notes.

<main class="mote-container" style="--mote-container-max: 42rem">
  <nav aria-label="breadcrumb">
    <ol><li><a href="/">Home</a></li><li><a href="/blog">Blog</a></li>
    <li><span aria-current="page">Article</span></li></ol>
  </nav>
  <h1>Article title</h1>
  <p><small class="mote-muted">October 2026 · 8 min read</small></p>
  <p>
    <a class="mote-badge" href="/tags/css">css</a>
    <a class="mote-badge" href="/tags/design">design</a>
  </p>
  <p>Article body…</p>
  <blockquote><p>A pull quote.</p><cite>— Someone</cite></blockquote>
  <figure>
    <img src="photo.jpg" alt="Caption">
    <figcaption>Photo credit</figcaption>
  </figure>
  <div class="mote-media">
    <img class="mote-avatar" src="author.jpg" alt="Author">
    <div>
      <p><strong>Author Name</strong></p>
      <p class="mote-muted">Bio line</p>
    </div>
  </div>
</main>

Long-form reading with notes

A chapter can pair a narrow reading column with a companion table of contents and numbered references. mote styles the semantic navigation and links; one page rule owns the grid and sticky rail. Keep the TOC label lowercase so the toc selector applies:

<style>
.reading-layout {
  display: grid;
  grid-template-columns: minmax(0, 42rem) minmax(12rem, 16rem);
  gap: clamp(2rem, 5vw, 5rem);
  align-items: start;
}
.reading-column { grid-column: 1; }
.reading-toc {
  grid-column: 2;
  grid-row: 1;
  position: sticky;
  top: 5rem;
}
@media (max-width: 50rem) {
  .reading-layout { grid-template-columns: 1fr; }
  .reading-column, .reading-toc { grid-column: 1; grid-row: auto; }
  .reading-toc { position: static; }
}
</style>

<main class="mote-container">
  <div class="reading-layout">
    <nav class="reading-toc" aria-label="toc">
      <p><strong>On this page</strong></p>
      <ul>
        <li><a href="#argument">Argument</a></li>
        <li><a href="#notes-heading">Notes</a></li>
      </ul>
    </nav>
    <article class="reading-column">
      <header>
        <h1>The Hour Before the Boats</h1>
        <p class="mote-muted">Chapter 4 · 8 min read</p>
      </header>
      <section id="argument">
        <h2>Argument</h2>
        <p>The harbor changed before dawn<sup>
          <a href="#note-1" id="ref-1">1</a>
        </sup></p>
      </section>
      <section aria-labelledby="notes-heading">
        <h2 id="notes-heading">Notes</h2>
        <ol>
          <li id="note-1">
            <p>The tide table records the first light.</p>
            <a href="#ref-1">Back to reference 1</a>
          </li>
        </ol>
      </section>
    </article>
  </div>
</main>

The narrow layout keeps the TOC before the article in source order and stacks it above the prose. The paired anchors make the reference and backlink explicit without adding JavaScript.

Login page

A focused auth screen — .mote-hero centers the card in the viewport, the card resets alignment so labels read normally inside the centered hero, .mote-stack stretches fields, and .mote-row + .mote-push split the remember-me line. The full-width submit is the one page rule — the stack stretches fields, not buttons:

<body>
  <main class="mote-container mote-hero" style="--mote-container-max: 26rem">
    <form class="mote-card mote-stack">
      <h1>Sign in</h1>
      <p><label for="email">Email</label>
        <input id="email" type="email" required></p>
      <p><label for="password">Password</label>
        <input id="password" type="password" required></p>
      <p class="mote-row">
        <label><input type="checkbox"> Remember me</label>
        <a class="mote-push" href="/reset">Forgot password?</a>
      </p>
      <p>
        <button type="submit" style="width:100%">Sign in</button>
      </p>
    </form>
    <p class="mote-muted">No account? <a href="/signup">Create one</a></p>
  </main>
</body>

Marketing hero

.mote-hero fills the viewport — right for 404s and logins, wrong for marketing, where the CTA must sit above the fold. A marketing hero is a plain centered section; the closing call-to-action band is .mote-band (Hero and bands):

<main>
  <section class="mote-container" style="text-align:center; padding-block:5rem 4rem">
    <span class="mote-badge mote-success">New — v0.8</span>
    <h1 class="mote-display">Ship plain HTML</h1>
    <p class="mote-muted">Zero classes required. Opt-in where semantics run out.</p>
    <p>
      <a class="mote-btn" href="/signup">Get started</a>
      <a class="mote-ghost" href="/docs">Read the docs</a>
    </p>
  </section>

  <section class="mote-band">
    <div class="mote-container" style="text-align:center">
      <h2>Ready when you are.</h2>
      <p><a class="mote-btn" href="/signup">Create account</a></p>
    </div>
  </section>
</main>

Billing toggle

The pricing-page idiom, CSS-only: hidden radios steer the prices with :checked ~ selectors. The radios must precede, as siblings, every element they steer — they sit bare in main, not in a p or fieldset. And .mote-sr-only is the wrong way to hide them — it doubles as a skip link on keyboard focus — so hide them yourself:

<style>
  main > input[type="radio"] { position: absolute; opacity: 0; }
  main > label {
    padding: var(--mote-control-pad, 0.5rem) 0.9rem;
    border-radius: var(--mote-radius-sm);
    cursor: pointer;
  }
  main > input:focus-visible + label { box-shadow: var(--mote-focus-ring); }
  #bill-monthly:checked + label,
  #bill-yearly:checked + label {
    background: var(--mote-accent);
    color: var(--mote-on-accent);
  }
  .yearly { display: none; }
  #bill-yearly:checked ~ * .monthly { display: none; }
  #bill-yearly:checked ~ * .yearly { display: inline; }
</style>

<main class="mote-container">
  <input type="radio" name="bill" id="bill-monthly" checked>
  <label for="bill-monthly">Monthly</label>
  <input type="radio" name="bill" id="bill-yearly">
  <label for="bill-yearly">Yearly <small class="mote-muted">−17%</small></label>

  <section>
    <span class="price"><span class="monthly">$24</span><span class="yearly">$20</span>/mo</span>
  </section>
</main>

Display pull-quote

Editorial pull-quote — compose blockquote with .mote-display on the quoted paragraph: the rule tints from the blockquote, the attribution stays body-scale:

<blockquote>
  <p class="mote-display" style="--mote-display: 1.75rem">
    Quotes carry more weight when they are larger than the prose around them.
  </p>
  <cite>— Every magazine, ever</cite>
</blockquote>

Row hover

mote ships zebra striping; attention-on-hover stays a page opinion. One token-reading rule covers both themes:

tbody tr:hover {
  background: var(--mote-accent-soft);
}

Feedback row

The end-of-article "was this helpful?" — a row, a solid and a ghost button, a pushed support link:

<p class="mote-row" style="margin-block-start:3rem">
  <span>Was this page helpful?</span>
  <button type="button">Yes</button>
  <button type="button" class="mote-ghost">Not really</button>
  <a class="mote-push" href="/support">Get support</a>
</p>

Toolbar row

Filter and action bars — a search, a select, quiet actions, a pushed count — one .mote-row. Controls keep intrinsic widths and equal heights:

<form class="mote-row" role="search">
  <label class="mote-sr-only" for="q">Filter</label>
  <input id="q" type="search" placeholder="Filter…">
  <label class="mote-sr-only" for="sort">Sort</label>
  <select id="sort"><option>Newest</option></select>
  <button type="submit" class="mote-ghost">Apply</button>
  <span class="mote-muted mote-push">12 of 48 shown</span>
</form>

Result rows

Poll results, skill bars, quota meters — label, bar, figure rows that align across different label lengths. A small grid does what a flex row can't:

<style>
  .results {
    display: grid;
    gap: 0.5rem 1rem;
    grid-template-columns: minmax(10rem, 1fr) minmax(8rem, 2fr) auto;
  }
</style>

<div class="results">
  <span>Cascade layers</span>
  <progress class="mote-success" value="1538" max="4812"></progress>
  <span class="mote-num">32.0%</span>
  <span>color-mix()</span>
  <progress value="1204" max="4812"></progress>
  <span class="mote-num">25.0%</span>
</div>

Price line

Product pricing — display scale for the number, a muted compare-at strike, plain-text stars. One inline --mote-display keeps the price huge without hijacking the whole line:

<p class="mote-display" style="--mote-display: 2.25rem; margin-block:0">
  $179 <s class="mote-muted" style="font-size: 1.15rem">$229</s>
</p>
<p class="mote-muted" style="margin-block-start:0">★★★★★ 4.6 — 312 reviews</p>

Post actions

The quiet action strip under forum posts and comments — muted links in a row; buttons only when an action is destructive:

<p class="mote-row mote-muted" style="gap: 1rem; margin-block: 0">
  <a href="#top">♥ 38</a>
  <a href="#top">Quote</a>
  <a href="#top">Reply</a>
  <a class="mote-push" href="#top">Report</a>
</p>

Growing input

Fields keep intrinsic width by design — but in a toolbar a promo or URL field should eat the remaining space. One page rule, token-safe:

<form class="mote-row">
  <input class="grow" type="text" placeholder="Promo code">
  <button type="submit">Apply</button>
</form>

<style>
  .grow { flex: 1; min-width: 8rem; }
</style>

Prominent search

Help-center and docs heroes want a big obvious search box — the canonical form plus one width rule:

<form class="mote-row" role="search" style="justify-content: center">
  <label class="mote-sr-only" for="q">Search</label>
  <input id="q" type="search" placeholder="How can we help?"
    style="width: min(100%, 30rem)">
  <button type="submit">Search</button>
</form>

Grouped messages

Consecutive chat or comment messages from the same sender: repeat .mote-media with an aria-hidden spacer the width of the avatar, so follow-ups align under the text rather than the face:

<div class="mote-media">
  <img class="mote-avatar" src="a.png" alt="Ada">
  <div>First message…</div>
</div>
<div class="mote-media">
  <span aria-hidden="true" style="flex: 0 0 var(--mote-avatar, 2.5rem)"></span>
  <div>Follow-up from the same sender…</div>
</div>

Weekend columns

Calendar grids: the zebra and the tr[aria-current] tint paint on the row, so column shading must be a background-image layered over the row color — a plain cell background would cover the current-row tint:

.weekend {
  background-image: linear-gradient(
    color-mix(in oklab, var(--mote-surface) 55%, transparent),
    color-mix(in oklab, var(--mote-surface) 55%, transparent)
  );
}
