Getting started

Install mote, understand its semantic-first contract, and learn the small token system that controls every theme.

Principles

  • Semantic HTML is the API. Elements are styled by what they are; classes exist only where the platform has no semantic carrier.
  • The platform before the library. Dialogs, popovers, accordions and validation use native features, quietly styled — mote never ships JavaScript to do what the browser already does.
  • Tokens all the way down. Every color, radius, shadow and status is a variable; derived tones are computed, never hand-tuned twice.
  • Weightless by default. One file for elements, an opt-in second file for components — zero bytes of library JavaScript.
  • Unobtrusive. Warm, soft, accessible; styling that never shouts.

Get started

Drop one file in your page and write plain HTML. Everything is styled by element — no utility classes, no framework, no build.

<!DOCTYPE html>
<html lang="en">
  <head>
    <link rel="stylesheet" href="mote.css">
    <title>That's it.</title>
  </head>
  <body>
    <h1>Hello, cozy.</h1>
  </body>
</html>

Out of the box, mote falls back to your system fonts; two link tags give it the intended look — see Fonts.

Optional components — cards, badges, popovers, accordions, spinners — live in a second stylesheet. Include it only if you use them:

<link rel="stylesheet" href="mote.css">
<link rel="stylesheet" href="mote.components.css">

This page is a live demo: it is styled by exactly those two files.

Theming

Every color, radius, shadow and font flows from --mote-* custom properties. Override a few tokens and the whole library re-themes — derived tones (focus rings, hover deepening, tinted surfaces) are computed with color-mix(), so you never hand-tune a second palette.

The cascade has three layers, each computed from the last: the base palette feeds derived tones (soft tints, hover deepening, focus rings — re-derived automatically whenever a base token changes), and status classes add a third indirection on top. Inheriting content surfaces read the --mote-status tokens with an accent fallback, while gated actions and badges declare their own status. Override the chain anywhere; everything downstream follows.

Live proof — this card re-themes everything inside it with two inline tokens:

<div class="mote-card" style="--mote-accent: #4a7a5b; --mote-on-accent: #ffffff">
  <h3>Re-themed card</h3>
  <p>A <a href="#">link</a>, a <button type="button">button</button> and a
    <span class="mote-badge mote-success">badge</span> — all from
    two variables.</p>
</div>

Re-themed card

A link, a and a badge — all from two variables. The focus ring, hover states and soft tints re-derived automatically.

:root {
  --mote-accent: #4a7a5b;    /* your brand color */
  --mote-on-accent: #ffffff; /* readable text on accent fills */
  --mote-bg: #fffdf5;        /* your paper */
  --mote-radius: 6px;        /* your edges */
}

When replacing --mote-accent, replace --mote-on-accent too: mote cannot infer whether white or dark text has enough contrast on an arbitrary brand color. A separate dark-theme accent may need its own foreground token as well.

Brand themes

A brand needs more than one declaration. mote's own palette rules are more specific than a plain :root override, so a lone :root { --mote-accent: … } is superseded in automatic dark mode and on paper. Restate the brand in every state it can appear in — and always pair the accent with its foreground token:

:root {
  --mote-accent: #4a7a5b;      /* brand in light and automatic light mode */
  --mote-on-accent: #ffffff;
}

:root[data-theme="dark"] {
  --mote-accent: #8fc7a1;      /* brand in forced dark mode */
  --mote-on-accent: #10231a;
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --mote-accent: #8fc7a1;    /* brand in automatic dark mode */
    --mote-on-accent: #10231a;
  }
}

@media print {
  :root,
  :root[data-theme="dark"],
  :root:not([data-theme="light"]) {
    --mote-accent: #4a7a5b;    /* brand on paper */
    --mote-on-accent: #ffffff;
  }
}

Those selectors match mote's own palette rules, so your values win by order — override only the tokens you need and every derived tone re-derives from the accent you set. The @media print block is the one most pages forget: mote prints on a light paper palette, so without it paper keeps mote's accent instead of yours.

The accent is deliberately plum: it is the one hue family that collides with none of the four semantic colors, so a link never looks like a status.

The toggle on this page is a few lines of JavaScript, including the .mote-theme-switch helper that prevents the stale-color bug. It also writes the current state into the button label — keep that line if your toggle shows which state is active:

const root = document.documentElement;
const states = ['', 'light', 'dark'];
const toggle = document.querySelector('#theme-toggle');
let i = 0;
toggle.addEventListener('click', () => {
  root.classList.add('mote-theme-switch');
  i = (i + 1) % states.length;
  root.dataset.theme = states[i];
  toggle.textContent = 'Theme: ' + (states[i] || 'auto');
  requestAnimationFrame(() => root.classList.remove('mote-theme-switch'));
});
