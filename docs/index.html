mote.css

The smallest thing that can carry style — a tiny, semantic, classless CSS layer for plain HTML. Zero dependencies, zero build step, zero JavaScript.

Principles

  • Semantic HTML is the API. Elements are styled by what they are; classes exist only where the platform has no semantic carrier.
  • The platform before the library. Dialogs, popovers, accordions and validation use native features, quietly styled — mote never ships JavaScript to do what the browser already does.
  • Tokens all the way down. Every color, radius, shadow and status is a variable; derived tones are computed, never hand-tuned twice.
  • Weightless by default. One file for elements, an opt-in second file for components — zero bytes of library JavaScript.
  • Unobtrusive. Warm, soft, accessible; styling that never shouts.

Get started

Drop one file in your page and write plain HTML. Everything is styled by element — no utility classes, no framework, no build.

<!DOCTYPE html>
<html lang="en">
  <head>
    <link rel="stylesheet" href="mote.css">
    <title>That's it.</title>
  </head>
  <body>
    <h1>Hello, cozy.</h1>
  </body>
</html>

Out of the box, mote falls back to your system fonts; two link tags give it the intended look — see Fonts.

Optional components — cards, badges, popovers, accordions, spinners — live in a second stylesheet. Include it only if you use them:

<link rel="stylesheet" href="mote.css">
<link rel="stylesheet" href="mote.components.css">

This page is a live demo: it is styled by exactly those two files.

Theming

Every color, radius, shadow and font flows from --mote-* custom properties. Override a few tokens and the whole library re-themes — derived tones (focus rings, hover deepening, tinted surfaces) are computed with color-mix(), so you never hand-tune a second palette.

The cascade has three layers, each computed from the last: the base palette feeds derived tones (soft tints, hover deepening, focus rings — re-derived automatically whenever a base token changes), and status classes add a third indirection on top, assigning --mote-status tokens that every note, badge and toast reads with an accent fallback. Override the chain anywhere; everything downstream follows.

Live proof — this card re-themes everything inside it with two inline tokens:

<div class="mote-card" style="--mote-accent: #4a7a5b">
  <h3>Re-themed card</h3>
  <p>A <a href="#">link</a>, a <button type="button">button</button> and a
    <span class="mote-badge mote-success">badge</span> — all from
    two variables.</p>
</div>

Dark mode

mote follows the user's system preference automatically. To force a theme, set an attribute on <html>:

<html data-theme="dark">  <!-- or "light" -->

The toggle on this page is five lines of JavaScript — no library involvement:

const root = document.documentElement;
document.querySelector('#theme-toggle').addEventListener('click', () => {
  root.dataset.theme = root.dataset.theme === 'dark' ? 'light' : 'dark';
});

Dialogs

Native <dialog> gets a soft surface, a dimmed blurred backdrop, and — with the components file — a gentle entrance animation. Opening a modal takes one line of JavaScript:

<dialog id="example">
  <h3>Modal title</h3>
  <p>Content…</p>
  <form method="dialog"><button>Close</button></form>
</dialog>

<script>
  document.querySelector('#open-btn').onclick = () =>
    document.querySelector('#example').showModal();
</script>

A cozy modal

Backdrop dim, gentle fade, native Esc-to-close. The form method="dialog" button closes it declaratively.

Details and accordions

Single <details> elements are soft cards. Give a group of siblings the same name and the browser turns them into an exclusive accordion — one open at a time, no JavaScript. Try it:

<details name="faq">
  <summary>Does it need a build step?</summary>
  <p>No.</p>
</details>
<details name="faq">
  <summary>Does it need classes?</summary>
  <p>No.</p>
</details>
Does it need a build step?

No. It is a single CSS file.

Does it need classes?

Not for elements. The optional components file adds a handful where no semantic element exists.

Does it need JavaScript?

No. Tooltips, menus and accordions ride on native platform features.

In Chromium engines, opening and closing also animates smoothly — a details pseudo-element nicety provided by the components file. Everywhere else the toggle is instant.

Popovers: tooltips and menus

The native popover attribute gives you top-layer, light-dismiss, Esc-to-close surfaces — styled by mote, wired by the browser. A popovertarget button toggles one with zero JavaScript:

<button popovertarget="tip">What is a mote?</button>
<div popover class="mote-tooltip" id="tip">
  A speck of dust, especially one drifting in a sunbeam.
</div>

<button popovertarget="menu">Options</button>
<menu popover id="menu" role="menu">
  <li><button role="menuitem">Rename</button></li>
  <li><button role="menuitem">Duplicate</button></li>
  <li><button role="menuitem">Archive</button></li>
</menu>

A speck of dust, especially one drifting in a sunbeam.

    • By default, the browser opens popovers centered in the viewport. To place one next to its trigger instead, use CSS anchor positioning (Chrome 125+, Safari 26+): give the trigger an anchor-name and the popover a matching position-anchor — mote then positions it right below the trigger and flips it when it would overflow the viewport. Engines without support keep the centered fallback:

    <button popovertarget="menu" style="anchor-name: --menu-a">Options</button>
<menu popover id="menu" style="position-anchor: --menu-a" role="menu">
  <li><button role="menuitem">Rename</button></li>
</menu>

    The live examples above are anchored — in Chromium and Safari they open next to their buttons; in Firefox they open centered.

    Helpers

    Three tiny escape hatches for what semantics cannot express:

    Status classes

    Statuses are pure token assignments. mote-success, mote-warning, mote-error, mote-info and mote-muted set the --mote-status and --mote-status-soft variables and nothing else — components consume the tokens and fall back to the accent color when no status is present:

    /* the status contract */
.mote-success {
  --mote-status: var(--mote-success);
  --mote-status-soft: var(--mote-success-soft);
}

/* base components only read the tokens */
.mote-badge {
  color: var(--mote-status, var(--mote-accent-deep));
  background: var(--mote-status-soft, var(--mote-accent-soft));
}

    No specificity to fight: restyle a status once and every note, badge and toast follows. Or set the variable inline — style="--mote-status: rebeccapurple" — on any status-consuming element.

    More than badges read the tokens — blockquote rules, progress and meter bars, spinners and summary markers pick them up too:

    Fonts

    mote declares font stacks only — it embeds nothing and requires nothing. Out of the box it falls back to your system fonts. For the full experience, add Inter and Commit Mono (both free, SIL OFL):

    <!-- CDN -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fontsource-variable/inter@5/index.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fontsource/commit-mono@5/index.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fontsource/commit-mono@5/700.css">

<!-- or self-host -->
npm install @fontsource-variable/inter @fontsource/commit-mono
