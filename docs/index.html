mote.css

The smallest thing that can carry style — a tiny, semantic, class-optional CSS layer for plain HTML. Zero dependencies, zero build step, zero JavaScript.

Principles

  • Semantic HTML is the API. Elements are styled by what they are; classes exist only where the platform has no semantic carrier.
  • The platform before the library. Dialogs, popovers, accordions and validation use native features, quietly styled — mote never ships JavaScript to do what the browser already does.
  • Tokens all the way down. Every color, radius, shadow and status is a variable; derived tones are computed, never hand-tuned twice.
  • Weightless by default. One file for elements, an opt-in second file for components — zero bytes of library JavaScript.
  • Unobtrusive. Warm, soft, accessible; styling that never shouts.

Get started

Drop one file in your page and write plain HTML. Everything is styled by element — no utility classes, no framework, no build.

<!DOCTYPE html>
<html lang="en">
  <head>
    <link rel="stylesheet" href="mote.css">
    <title>That's it.</title>
  </head>
  <body>
    <h1>Hello, cozy.</h1>
  </body>
</html>

Out of the box, mote falls back to your system fonts; two link tags give it the intended look — see Fonts.

Optional components — cards, badges, popovers, accordions, spinners — live in a second stylesheet. Include it only if you use them:

<link rel="stylesheet" href="mote.css">
<link rel="stylesheet" href="mote.components.css">

This page is a live demo: it is styled by exactly those two files.

Theming

Every color, radius, shadow and font flows from --mote-* custom properties. Override a few tokens and the whole library re-themes — derived tones (focus rings, hover deepening, tinted surfaces) are computed with color-mix(), so you never hand-tune a second palette.

The cascade has three layers, each computed from the last: the base palette feeds derived tones (soft tints, hover deepening, focus rings — re-derived automatically whenever a base token changes), and status classes add a third indirection on top, assigning --mote-status tokens that every note, badge and toast reads with an accent fallback. Override the chain anywhere; everything downstream follows.

Live proof — this card re-themes everything inside it with two inline tokens:

<div class="mote-card" style="--mote-accent: #4a7a5b">
  <h3>Re-themed card</h3>
  <p>A <a href="#">link</a>, a <button type="button">button</button> and a
    <span class="mote-badge mote-success">badge</span> — all from
    two variables.</p>
</div>

Tables

Numeric figures align automatically — mote sets font-variant-numeric: tabular-nums on every td. Right-align a whole column with the opt-in .mote-num class on its cells; when you want the tabular figures without the alignment (day numbers, headline figures, meta lines), use .mote-tabular instead:

<th class="mote-num">Price</th>
<td class="mote-num">$24</td>

For sticky headers and scrollable data tables, wrap in the opt-in .mote-table-scroll — the header row sticks, wide tables scroll inside the wrapper, never the page. Cap the panel height with --mote-table-max (default 60vh); the sticky header engages once the wrapper actually scrolls. Inside the wrapper, cell borders are drawn per side — Chromium paints collapsed borders at the flow position, not with the sticky cell:

<div class="mote-table-scroll">
  <table>…</table>
</div>

<!-- dense panels: cap the height -->
<div class="mote-table-scroll" style="--mote-table-max: 24rem">
  <table>…</table>
</div>

Mark the current row with aria-current — the same vocabulary as nav pills. The tint reads over zebra (the regression fixture asserts it on both parities):

<tr aria-current="true">…</tr>

Captions center by default; a quiet left-aligned caption is one page rule: caption { text-align: start }.

Forms

Labels, inputs, selects, checkboxes, radios and buttons inherit the cozy surface. Invalid fields show a brick border once the user interacts with them (:user-invalid).

Fields keep their intrinsic width — for stacked forms, add input, select, textarea { width: 100% } in your page styles; inline forms are equally valid, so mote does not decide for you.

Or use the opt-in .mote-stack class — a vertical rhythm for forms and lists: children space by --mote-stack-gap (default 1.25rem) with their block margins zeroed, fields stretch full width, checkboxes/radios stay at 1em. It stacks any content, not just forms. On a <fieldset> it flattens the native legend notch — the legend renders as the first line inside the box, which reads fine for most forms:

<form class="mote-stack">
  <p><label for="name">Name</label> <input id="name" type="text"></p>
</form>

File inputs get a minimal drop-zone treatment — a dashed border and the same density tokens as every other control, so their height matches sibling fields in a stack.

Programmatic validation: aria-invalid="true" gets the same brick border as :user-invalid, so server-side and failed-save states are styleable without waiting for user interaction. A canonical search form (sr-only label + inline row):

<form class="mote-row" role="search">
  <label class="mote-sr-only" for="q">Search</label>
  <input id="q" type="search" placeholder="Search…">
  <button type="submit">Go</button>
</form>

Buttons and statuses

All button styles — solid and ghost — are gated: the status class must sit on the button itself. A themed section — an error note, a toast, a page-level body class="mote-error" — never recolors the actions inside it. Statuses theme content; they never theme actions. The intent of an action is declared at the action site:

<button>Neutral action</button>
<button class="mote-error">Delete forever</button>
<button class="mote-ghost">Quiet action</button>
<button class="mote-ghost mote-success">Confirm quietly</button>

Ghost buttons follow the same law. Inside a themed section, a ghost stays accent-tinted; to make it match the section's status, put the status class on it explicitly — class="mote-ghost mote-error" for a quiet destructive, class="mote-ghost mote-success" for a quiet confirm. Ghosts work on buttons and anchors alike.

<button class="mote-ghost">Cancel</button>
<a class="mote-ghost" href="/docs">Read the docs</a>
<button class="mote-ghost mote-error">Delete draft</button>

Details and accordions

Single <details> elements are soft cards. Give a group of siblings the same name and the browser turns them into an exclusive accordion — one open at a time, no JavaScript. Try it:

<details name="faq">
  <summary>Does it need a build step?</summary>
  <p>No.</p>
</details>
<details name="faq">
  <summary>Does it need classes?</summary>
  <p>No.</p>
</details>
Does it need a build step?

No. It is a single CSS file.

Does it need classes?

Not for elements. The optional components file adds a handful where no semantic element exists.

Does it need JavaScript?

No. Tooltips, menus and accordions ride on native platform features.

In Chromium engines, opening and closing also animates smoothly — a details pseudo-element nicety provided by the components file. Everywhere else the toggle is instant.

Printing note: the browser enforces one open panel per exclusive group, so printing "everything open" needs a beforeprint listener that removes the name attribute (and restores it after). The print stylesheet already forces the light palette, so dark-mode users get paper colors, not ink floods.

Print helpers: .mote-no-print hides any element on paper; .mote-print-only shows only in print:

<header class="mote-no-print">…</header>
<p class="mote-print-only">Printed notice</p>

Summary markers read the status classes too — moss, honey, brick, dusty-blue or neutral markers, from one class on the details element:

<details class="mote-success">
  <summary>A summary with a moss-green marker</summary>
  <p>Content…</p>
</details>

  <li><button role="menuitem">Archive</button></li>

    Layout

    Layout pieces from mote.components.css — default modern CSS, no JavaScript, no column utilities, no breakpoints. The document shell below is the whole story: header, nav, aside and footer flex from plain landmarks, and the sticky translucent header on this very page is the same pattern. The semantic selectors (nav[aria-label]) match their values case-sensitively — copy the exact lowercase ("breadcrumb", "pagination", "toc").

    Simple page

    Most pages need nothing more than a sticky header and a centered column — exactly the layout of the page you are reading. The header bar and its pill nav style themselves from landmarks; the classes on the inner div are the layout: .mote-container adds the gutters, .mote-row flexes, .mote-brand quiets the wordmark, .mote-push right-aligns the last control:

    Header and navigation

    Direct children of <body> get these styles from landmarks alone. The classes exist for one case landmarks cannot express — a shell wrapped in a <div>, where body > header cannot reach it:

    <header class="mote-header">
  <nav class="mote-nav">
    <ul>
      <li><a href="/" aria-current="page">Home</a></li>
      <li><a href="/docs">Docs</a></li>
    </ul>
  </nav>
</header>

    Long navs scroll horizontally inside the bar — a section list of any length keeps the header one line, and the brand and pushed controls keep their place. Under the pills a hairline carries directional fades that bloom toward whichever side holds more content. Pure CSS cannot tell "at the start" from "nothing to scroll", so the fades key off a data-nav attribute kept current by the seven-line snippet below — without it there is no line at all: zero-JS headers keep just the pills, and the cut pill is the overflow signal. With the snippet, the hairline appears only while the nav actually scrolls: a single pill leaves nothing on the line — and on wide viewports, where the pills never overflow, there is nothing to see at all. The snippet's math is direction-agnostic; the gradients flip under [dir="rtl"]. Breadcrumbs need no class at all — mote styles the semantic pattern:

    const pills = document.querySelector('header nav ul');
const sync = () => pills.parentElement.dataset.nav =
  (pills.scrollLeft > 1 ? 'start ' : '') +
  (pills.scrollLeft + pills.clientWidth < pills.scrollWidth - 1 ? 'end' : '');
pills.addEventListener('scroll', sync, { passive: true });
addEventListener('resize', sync);
sync();
document.fonts?.ready.then(sync);  // pill widths change when webfonts load

  <ol>

    Badges

    Helpers

    Escape hatches for what semantics cannot express — the helpers, plus the status classes every status-consuming component reads:

    Status classes

    Statuses are pure token assignments. mote-success, mote-warning, mote-error, mote-info and mote-muted set the --mote-status and --mote-status-soft variables and nothing else — components consume the tokens and fall back to the accent color when no status is present:

    Two more classes control inheritance — status tokens cascade, so a badge inside .mote-error inherits the brick tint. .mote-default forces the accent down the tree ("keep this plum regardless of context"); .mote-reset clears the inherited status so each element's own classes decide:

    <span class="mote-badge mote-default">forced plum</span>
<div class="mote-reset">
  <span class="mote-badge">fell back to accent</span>
</div>

    /* the status contract */
.mote-success {
  --mote-status: var(--mote-success);
  --mote-status-soft: var(--mote-success-soft);
}

/* base components only read the tokens */
.mote-badge {
  color: var(--mote-status, var(--mote-accent-deep));
  background: var(--mote-status-soft, var(--mote-accent-soft));
}

    No specificity to fight: restyle a status once and every note, badge and toast follows. Or set the variable inline — style="--mote-status: rebeccapurple" — on any status-consuming element.

    Status classes are token carriers, not text colors: a plain mote-success on a paragraph does not recolor its text. For tinted text, write color: var(--mote-success) in your page CSS — the tokens are yours to read.

    Billing toggle

    The pricing-page idiom, CSS-only: hidden radios steer the prices with :checked ~ selectors.   main > input[type="radio"] { position: absolute; opacity: 0; }

    padding: var(--mote-control-pad, 0.5rem) 0.9rem;
    border-radius: var(--mote-radius-sm);
    cursor: pointer;
  }
  main > input:focus-visible + label { box-shadow: var(--mote-focus-ring); }
  #bill-monthly:checked + label,
  #bill-yearly:checked + label {
    background: var(--mote-accent);
    color: var(--mote-on-accent);
  }
  .yearly { display: none; }
  #bill-yearly:checked ~ * .monthly { display: none; }
  #bill-yearly:checked ~ * .yearly { display: inline; }
</style>

    mote declares font stacks only — it embeds nothing and requires nothing. Out of the box it falls back to your system fonts. For the full experience, add Inter and Commit Mono (both free, SIL OFL):

    <!-- CDN -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fontsource-variable/inter@5/index.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fontsource/commit-mono@5/index.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@fontsource/commit-mono@5/700.css">

<!-- or self-host -->
npm install @fontsource-variable/inter @fontsource/commit-mono
