Helpers and print

Use these escapes only when semantics cannot carry the distinction. Helpers remain opt-in; print rules stay separate from screen styling.

Helpers

Escape hatches for what semantics cannot express — the helpers, plus the status classes every status-consuming component reads:

Status classes

.mote-success, .mote-warning, .mote-error and .mote-info are pure token assignments: they set the --mote-status and --mote-status-soft variables and nothing else. .mote-muted also dims text directly and carries the neutral status tokens. Status-consuming surfaces read those tokens; most fall back to accent. See Semantic feedback for the role-specific error/info fallbacks:

Status tokens cascade through inheriting content surfaces. Buttons and badges are gated: they declare their own status and never inherit an ancestor's tint — see Badges and Buttons and statuses.

Two more classes control inheritance for the surfaces that consume those tokens. .mote-default sets an explicit accent status for inheriting surfaces in that subtree ("keep this plum in this section"); gated controls still use their own status classes. .mote-reset clears the inherited status so the surface falls back to accent:

<div class="mote-error">
  <div class="mote-note">Inherits the brick status.</div>

  <div class="mote-reset">
    <div class="mote-note">Falls back to accent.</div>
  </div>
</div>

/* the status contract */
.mote-success {
  --mote-status: var(--mote-success);
  --mote-status-soft: var(--mote-success-soft);
}

/* inheriting surfaces only read the tokens */
.mote-note {
  color: var(--mote-status, var(--mote-accent-deep));
  background: var(--mote-status-soft, var(--mote-accent-soft));
}

No specificity to fight: restyle a status once and every inheriting content surface follows. Gated buttons and badges follow their own status class. Or set the variable inline — style="--mote-status: rebeccapurple" — on any status-consuming element.

Status classes are token carriers, not text colors: a plain mote-success on a paragraph does not recolor its text. For tinted text, write color: var(--mote-success) in your page CSS — the tokens are yours to read.

Two rules cover the whole status system. Inheriting surfaces take the nearest status in the tree; gated surfaces declare their own and never inherit an ancestor's tint. Progress and meter are inheriting surfaces: a bar inside a themed row takes that row's status unless it carries its own class, while a badge or button in the same row never does. To steer inheritance, .mote-default pins accent status for a subtree and .mote-reset clears the inherited one:

Notes and callouts

Two mechanisms cover note-like surfaces. .mote-note is the callout box — the component for info panels, warnings, confirmations. A blockquote with a status class is the quote treatment — a tinted rule, quieter than a box. Both are content surfaces: they inherit status from an ancestor, and both fall back to the accent when no status is present:

<div class="mote-note">Plain, accent tint</div>
<div class="mote-note mote-success">Saved. Everything is fine.</div>
<div class="mote-note mote-info">Heads up — a gentle fact.</div>
<div class="mote-note mote-warning">Careful now.</div>
<div class="mote-note mote-error">Something went softly wrong.</div>
<div class="mote-note mote-muted">A neutral fact, quietly stated.</div>
Plain, accent tint — the default note.

In centered sections a note stretches full width; for a callout-sized box: style="width: fit-content; margin-inline: auto".

Print and paper

mote prints on a light paper palette in either theme. Use the print helpers when the screen and the page need different content, then add page CSS for the document-specific parts such as orientation and page breaks.

Paper checklist

  • Keep the light paper palette; repeat brand accent overrides for print.
  • Use .mote-no-print for navigation, filters, and interactive-only controls.
  • Use .mote-print-only for paper-only contact details and instructions.
  • Check table completeness, orientation, and browser-dependent repeated headings.
  • Keep records, totals, and disclosure panels together where appropriate with break-inside.
  • Decide whether forms print; prefer a paper-only summary over split controls.
  • Inspect the generated PDF, not only print-media emulation.

Screen-only and paper-only content

.mote-no-print removes screen chrome from paper. .mote-print-only stays hidden on screen and appears on paper:

<nav class="mote-no-print">Site navigation</nav>
<div class="mote-print-only">Printed at the visitor’s request</div>

Tables, disclosures, and page breaks

With mote.components.css, .mote-table-scroll removes the screen height cap and clipping on paper. This guarantees that the complete table is present without artificial clipping; it does not guarantee that an arbitrary wide matrix fits narrow paper.

The .mote-doc shell itself does not choose a paper layout. That remains page-owned: collapse the screen grid, remove the shell gutter, and let the main region show its complete content. Mark navigation and other screen chrome with .mote-no-print when it should not appear on paper:

@media print {
  body.mote-doc {
    display: block;
    padding-inline: 0;
  }
  body.mote-doc > main {
    overflow: visible;
  }
}

This is the boundary between mote's component behavior and the page's print design. The complete light palette and table expansion are shipped; the shell's paper arrangement is not.

For a document or dedicated print output containing a dense matrix, landscape paper may be clearer than forcing many columns into portrait. This @page rule applies to the whole printed document:

@page {
  size: landscape;
  margin: 12mm;
}

For a document that mixes portrait and landscape sections, keep the landscape matrix in a separate print document rather than applying this rule to every page.

Check the generated PDF. Reducing type and padding can fit more columns but may force words to break; when many columns cannot remain legible, use the semantic record layout from Narrow screens: scroll or transform instead of forcing the matrix onto the page.

Chromium repeats a tfoot totals row at the top of each continuation page, where its colspan cells no longer line up with the columns. The data is complete; the repeated row is browser pagination. Keep the totals in tbody when the alignment matters.

mote's sticky site header goes static on paper, so it does not repeat over every page. A print-specific layout may restore position: sticky, but repetition across pages depends on the browser's paged-media implementation and is not guaranteed. Inspect the generated PDF; use the print engine's page-header mechanism when every page must carry a running head.

The phone-record layout keeps the table a table on paper: the recipe's print guard restores the hidden header row and the caption.

Keep important tables intact with a small page rule:

@media print {
  .receipt, tr, figure { break-inside: avoid; }
}

A closed details element does not guarantee that its hidden content reaches paper. If a manual must print every disclosure, open them in a beforeprint handler and restore their previous state in afterprint. Exclusive groups also need their shared name removed while printing, or the browser allows only one panel open. This complete page-level handler selects every disclosure, including unnamed panels, and preserves the original state:

const disclosures = [...document.querySelectorAll('details')];
let printState = [];

addEventListener('beforeprint', () => {
  if (printState.length === 0) {
    printState = disclosures.map(details => ({
      details,
      name: details.getAttribute('name'),
      open: details.open
    }));
  }
  for (const { details, name } of printState) {
    if (name !== null) details.removeAttribute('name');
    details.open = true;
  }
});

addEventListener('afterprint', () => {
  for (const { details, name, open } of printState) {
    if (name !== null) details.setAttribute('name', name);
    details.open = open;
  }
  printState = [];
});

Print helpers live in the helper map, but this section keeps the complete disclosure workflow together.
